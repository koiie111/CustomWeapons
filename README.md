# CustomWeapons

[![Build and test](https://github.com/koiie111/CustomWeapons/actions/workflows/build.yml/badge.svg)](https://github.com/koiie111/CustomWeapons/actions/workflows/build.yml)
[Скачать последнюю сборку](https://github.com/koiie111/CustomWeapons/releases/latest)

Самостоятельный плагин **CounterStrikeSharp / CS2 на .NET 10** для замены моделей оружия. Игрок выбирает скин в центральном меню, доступы проверяются в существующей MySQL-базе, выбор сохраняется локально. VIPCore и сторонний плагин меню не требуются.

**Статус v1.0.2:** сборка и автоматические тесты предусмотрены в CI, включая MySQL 8.4 с пользователем только для чтения. Работа конкретных моделей от первого/третьего лица, ножей, гранат и событий на живом CS2-сервере пока **не проверена**. Перед рабочим сервером выполните [игровую проверку](docs/TESTING.md).

## Требования

- CS2 dedicated server на Linux x64 или Windows x64.
- Metamod:Source и **CounterStrikeSharp 1.0.375 или совместимее**, с runtime **.NET 10**. API закреплён на `1.0.375`; обновления игры могут требовать обновления CounterStrikeSharp.
- MySQL 8.x с уже существующими `cw_access` и `cw_skins`. Проверка в CI использует MySQL 8.4. MariaDB отдельно не проверялась.
- Модели `.vmdl` и все зависимости должны быть доступны серверу **и клиентам**, например через используемый сервером Workshop-контент. Файлы моделей не входят в релиз, права на них остаются у авторов.

## Установка

1. Скачайте `CustomWeapons-v1.0.2.zip` из [Releases](https://github.com/koiie111/CustomWeapons/releases).
2. Распакуйте папку `addons` в `game/csgo/` вашего сервера.
3. Настройте `game/csgo/addons/counterstrikesharp/configs/plugins/CustomWeapons/CustomWeapons.json`.
4. Установите контент с моделями и зависимостями на сервер и обеспечьте его получение клиентами.
5. Перезапустите сервер либо загрузите плагин и **смените карту**. Предварительная загрузка ресурсов выполняется только при запуске/смене карты. После горячей загрузки плагин блокирует новые установки до смены карты.
6. Откройте `!cw` или `!customweapons` в чате. В консоли игрока доступны `css_cw` и `css_customweapons`.

```text
game/csgo/addons/counterstrikesharp/
├── plugins/CustomWeapons/
│   ├── CustomWeapons.dll
│   ├── CustomWeapons.Core.dll
│   ├── CustomWeapons.deps.json
│   ├── CustomWeapons.runtimeconfig.json
│   ├── MySqlConnector.dll
│   └── ... зависимости из архива
└── configs/plugins/CustomWeapons/CustomWeapons.json
```

Не копируйте `CounterStrikeSharp.API.dll` в каталог плагина: API предоставляет сервер.

## Конфигурация

Полный пример с шестью скинами: [configs/CustomWeapons.json](configs/CustomWeapons.json).

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `ConfigVersion` | `1` | Версия формата CounterStrikeSharp |
| `ServerId` | `1` | ID сервера; `0` учитывает доступы со всеми `sid` |
| `CooldownSeconds` | `1` | Пауза между ручными выборами/сбросами одного игрока; `0` отключает |
| `SaveSelections` | `true` | Сохранять выбор в JSON; `false` — только до отключения |
| `RefreshIntervalSeconds` | `60` | Обновление каталога и доступов; минимум 5 секунд |
| `Database` | см. пример | Подключение MySQL |
| `Weapons` | 4 категории | Классы оружия и их скины |

`SaveSelections` заменяет старый параметр `use_client_cookies`: это **серверное JSON-хранилище**, а не cookies клиента и не новая таблица MySQL.

### MySQL

```json
"Database": {
  "Host": "127.0.0.1",
  "Port": 3306,
  "Database": "customweapons",
  "Username": "customweapons",
  "Password": "",
  "PasswordEnvironmentVariable": "CW_DB_PASSWORD",
  "SslMode": "Preferred",
  "TimeoutSeconds": 10
}
```

Пароль берётся из переменной окружения `CW_DB_PASSWORD`, если она существует; иначе — из `Password`. Переменная должна быть доступна процессу сервера. Можно задать другое имя либо пустую строку для использования только поля `Password`. Не публикуйте заполненный конфиг. Для удалённой базы с настроенными сертификатами используйте `SslMode: "VerifyFull"`; `Preferred` соответствует примеру для локального подключения.

Пользователю БД достаточно `SELECT` на `cw_access` и `cw_skins`. Плагин не создаёт таблицы, не добавляет индексы и не изменяет строки. Выдача/продление/отзыв доступа остаются задачей существующего магазина или панели.

### Добавление скина

```json
"weapon_awp": {
  "Name": "AWP",
  "Skins": {
    "awp_animes": {
      "Name": "AWP - Перлика",
      "Model": "models/weapons/kolka/pak_4/awp/awp_animes.vmdl",
      "Private": true,
      "Hide": true
    }
  }
}
```

- `awp_animes` — идентификатор скина, совпадающий с `cw_access.model` и при наличии с `cw_skins.model`. Он уникален во всём конфиге, регистр значим, длина до 64 символов. Это **не путь модели**.
- `Model` — путь ресурса, начинающийся с `models/` и заканчивающийся на `.vmdl`, с прямыми `/`.
- `Private: true` требует доступ из `cw_access`; `false` разрешает скин всем.
- `Hide: true` скрывает скин без доступа; `false` показывает заблокированным. Игроку всегда доступен пункт стандартной модели.
- JSON определяет наличие скина и класс оружия. Отсутствующая строка `cw_skins` не блокирует его. Если строка есть, непустое `name` заменяет имя из JSON, а `active != 1` исключает скин. Конфликтующие дубликаты `model` блокируются и отмечаются в журнале.
- `price`, `fake_price`, `is_discount`, `type`, `video`, `img` не используются. Покупки и выдача доступов в плагин не входят.

После изменения конфигурации перезагрузите плагин и смените карту. Значения путей и идентификаторов из исходного примера, включая `m4a1s_daeldalus` и `awp_isane`, сохранены буквально: проверьте их соответствие вашему контенту.

### Сервер и срок доступа

Доступ относится к точному SteamID64 и идентификатору скина:

- `cw_access.sid = 0` — глобальный доступ.
- `ServerId = 0` в конфиге — принимать доступы с любым `sid`.
- Иначе требуется `sid = ServerId` либо `sid = 0`.
- `expires = 0` — бессрочно; иначе Unix-время в **секундах**, строго больше текущего времени UTC. Миллисекунды не поддерживаются.
- Из нескольких совпавших записей достаточно одной действующей.

Проверка загружается при подключении, затем с заданным интервалом. Истечение уже загруженного доступа проверяется непосредственно при применении, без ожидания обновления. Изменения в БД видны после ближайшего успешного опроса. Пока приватные доступы не загружены или после ошибки БД, новые применения приватных скинов запрещены. Публичные скины доступны, кроме явно отключённых в последнем успешно прочитанном каталоге.

## Выбор и передача оружия

- Меню: категория оружия → скин / «Стандартная модель». Управление — стандартное для центрального меню CounterStrikeSharp.
- По одному выбору на SteamID64 и категорию, без разделения по командам. Выбирать можно до покупки оружия и будучи мёртвым.
- Если игрок ещё не делал выбор для категории, автоматически используется первый доступный скин в порядке `Skins` конфигурации. Модель должна быть precached; приватный доступ проверяется после ответа MySQL с учётом `sid`, `expires` и каталога.
- Ручной выбор имеет приоритет, в том числе явный выбор «Стандартная модель». Автовыбор не записывается как ручное предпочтение. При недоступности сохранённого скина новые экземпляры остаются стандартными, другой скин автоматически не подставляется; сохранённый выбор не удаляется.
- Ручной выбор применяется к соответствующим экземплярам в инвентаре живого игрока и к будущему оружию. Отсутствующий или недоступный сохранённый скин не применяется.
- Уже оформленный экземпляр **сохраняет модель при выбрасывании и подборе**, даже если у получателя нет доступа или у него выбран другой скин.
- Новый владелец может явно выбрать свой доступный скин либо сбросить модель. Сброс не требует доступа к прежнему скину.
- Истечение, отзыв доступа и `active != 1` запрещают новые применения, но не снимают уже нанесённую модель. После уничтожения экземпляра она не переносится на новое оружие без действующего доступа.
- Плагин не выдаёт оружие, не меняет урон, боезапас, экономику, subclass и игровой тип ножа.

### Ножи и гранаты

Поддержка не ограничена четырьмя категориями примера: добавляйте существующие классы `weapon_*`. M4A1-S, USP-S, CZ75-Auto, Revolver и MP5-SD распознаются с учётом `ItemDefinitionIndex`.

`weapon_knife` служит общей категорией ножей, когда нет точного совпадения класса. Если движок сообщает общий класс для конкретного ножа, используйте общую категорию: плагин не создаёт отдельные игровые типы ножей.

Для HE, flashbang, smoke, decoy, molotov/incendiary и snowball предусмотрен перенос модели фактически удерживаемой гранаты на брошенный снаряд. Он использует краткий снимок сущности гранаты, а не выбранный скин нового владельца. Произвольные снаряды других плагинов автоматически не сопоставляются. Модель должна быть пригодна для использования на снаряде; эта часть требует игровой проверки.

## Сохранение и обновление

Выбор хранится в `plugins/CustomWeapons/data/selections.json`, запись выполняется последовательно через временный файл и замену. Сделайте резервную копию этого каталога и конфига перед обновлением. Повреждённый JSON копируется в `.corrupt-<UTC timestamp>` перед созданием новых данных. При ошибке записи выбор остаётся в памяти, но может не пережить перезапуск; причина отмечается в журнале.

При обновлении заменяйте файлы плагина, сохраняя **свой конфиг и каталог data**. При корректной выгрузке текущие модели возвращаются к исходным. После горячей перезагрузки смените карту для precache. Аварийное завершение процесса не гарантирует завершения последних записей на диск.

## Диагностика

В v1.0.2 игровые обработчики и опрос игроков запускаются после готовности карты. В логе должны появиться `CustomWeapons 1.0.2 loaded; waiting for map readiness.` и затем `CustomWeapons runtime ready; player access refresh started.`

После краша `A callback was made on a garbage collected delegate` полностью остановите процесс сервера, замените файлы плагина (сохранив конфиг и `data`) и запустите заново. Горячая замена не очищает уже оставшиеся в нативном движке callbacks. Исправлен сценарий раннего `GetPlayers` и аварийной выгрузки CustomWeapons; сама строка ошибки не определяет владельца callback. Если ошибка повторится на v1.0.2, нужны полный лог от запуска (особенно `Failed to load plugin`) и core dump.

| Симптом | Что проверить |
| --- | --- |
| В меню только стандартная модель | `Private/Hide`, точный SteamID64 и ID скина, `sid`, `expires`, подключение MySQL, `active` |
| «После смены карты» | Плагин загружен в середине карты; смените карту |
| Ошибка обновления MySQL | Адрес, порт, имя БД, пароль, SSL и права SELECT; код не выводит пароль/строку подключения |
| Скин отсутствует в каталоге | Позиция в JSON, конфликтующие строки `cw_skins`, `active` |
| Модель невидима / ошибка ресурса | Наличие `.vmdl` и материалов у клиента и сервера, точность регистра пути, совместимость модели |
| После подбора остаётся чужой скин | Это ожидаемо; выберите свой скин или стандартную модель вручную |
| Выбор не сохраняется | `SaveSelections`, права записи в `plugins/CustomWeapons/data`, ошибки диска |

Не используйте несколько плагинов, одновременно меняющих модель одного оружия: порядок их обработчиков может менять результат.

## Разработка и тесты

Нужен **.NET 10 SDK**, Git; PowerShell 7 нужен только для скрипта упаковки.

```sh
dotnet restore --locked-mode
dotnet build -c Release --no-restore
dotnet test -c Release --no-build
pwsh -File scripts/package.ps1
```

Архив и `SHA256SUMS.txt` появятся в `artifacts/`. MySQL-интеграция локально пропускается без `CW_TEST_MYSQL`; CI запускает её в отдельной одноразовой БД. Подробности и игровой чек-лист: [docs/TESTING.md](docs/TESTING.md).
