# CustomWeapons HUD bridge v1

`CustomWeapons.Hud.Api` is the canonical public contract. CounterStrikeSharp must load exactly one copy as a shared assembly at `addons/counterstrikesharp/shared/CustomWeapons.Hud.Api/CustomWeapons.Hud.Api.dll` before either plugin resolves it. Both plugins reference that shared type; do not package independent runtime copies in their plugin folders. The current CSS loader discovers shared folders on its first assembly resolution; adding this file to an already running process may require a scoped server restart. This repository does not install or restart anything.

The capability name is `customweapons:hud:v1`. Its provider is the stable singleton factory `HudBridgeRegistry.Provider` in the shared DLL, not a lambda capturing a plugin. A CW load swaps in a current service; unload clears only that exact service. `Generation` increments on each replacement and successful clear. Capture it before and after `GetSnapshot` and reject changes during a later write; stale service callbacks are converted to Deferred. Duplicate provider registrations caused by hot reload therefore cannot select an obsolete plugin instance.

All bridge calls and completion callbacks run on the game thread; the `Generation` scalar alone may be read from a worker thread. `GetSnapshot` describes configured models and explicit load/map/database/website readiness; callers must fail closed when the capability is missing or readiness, database or server ID disagree. `DatabaseServerUuid` and `DatabaseName` come from the same DB connection used for the snapshot; if that server cannot supply a valid UUID, identity and HUD readiness remain unavailable. `RequestRefresh` is called only after the website selection transaction commits. It initiates/coalesces a fresh CW DB read and checks Steam ID, controller, slot, team and map generation. `Reconciled` means the exact persisted selection was observed and the current CW cache resolves it. It does not confirm visual/native model application. `Superseded` means the persisted choice differs; `Deferred` indicates no current suitable game context or application eligibility; `Error` means the refresh failed. The existing CW commands, SQL ownership and native held-weapon logic remain in use.

Run `dotnet run --project tests/Runtime/Runtime.csproj -c Release` and `dotnet test tests/CustomWeapons.Tests/CustomWeapons.Tests.csproj -c Release`. The runtime suite exercises post-request read coalescing, exact selection, map end and unload/reload lifecycle with managed doubles; it is not a live CS2 proof.
